# Лабораторная работа №2 — Клиент и сервер: передача текстовой строки через TCP-сокет

Две программы обмениваются текстовой строкой по протоколу TCP: клиент читает строку с клавиатуры, подключается к серверу, отправляет её и отключается, а сервер ждёт подключений на порту 5050 и для каждого клиента печатает его адрес и присланную строку. Файлы: `Server.java` — сервер, `Client.java` — клиент.

## Запуск

Нужна Java 25 или новее. Из папки `lab2`:

```bash
java Server.java   # в первом терминале, остановка — Ctrl+C
java Client.java   # во втором терминале, можно запускать много раз
```

Для запуска на двух компьютерах в `Client.java` вместо `"127.0.0.1"` указывается IP-адрес компьютера с сервером; его показывает `ipconfig` (Windows) или `ifconfig` (macOS, Linux). Брандмауэр на сервере должен пропускать подключения к порту 5050.

## Пример вывода

Клиент (три запуска, в третьем в `Client.java` указан адрес `192.168.1.12`):

```
Строка: Привет, сервер!
Строка: Hello, TCP
Строка: Привет из локальной сети
```

Сервер:

```
/127.0.0.1:64978 Привет, сервер!
/127.0.0.1:64979 Hello, TCP
/192.168.1.12:64980 Привет из локальной сети
```

До `/` Java печатает имя хоста (оно не определялось, поэтому пусто), после — IP-адрес и порт клиента. Порт клиента выбирает ОС, для каждого подключения новый; фиксированный порт нужен только серверу.

## Как это работает

- `new ServerSocket(5050)` создаёт TCP-сокет сервера, привязывает его к порту 5050 на всех сетевых интерфейсах и включает ожидание подключений.
- `server.accept()` ждёт клиента и возвращает отдельный сокет `conn` для обмена с ним; цикл `while (true)` обслуживает клиентов одного за другим.
- `conn.getInputStream().readAllBytes()` читает всё, что прислал клиент, до закрытия соединения, `new String(...)` превращает байты в строку, `conn.getRemoteSocketAddress()` возвращает адрес клиента. После печати `conn.close()` закрывает соединение.
- Клиент: `IO.readln("Строка: ")` читает строку, `new Socket("127.0.0.1", 5050)` создаёт TCP-сокет и подключается к серверу, `text.getBytes()` переводит строку в байты, `getOutputStream().write(...)` отправляет их, `socket.close()` закрывает соединение — для сервера это признак конца строки.

## Особенности реализации

- **TCP.** `Socket` и `ServerSocket` в Java — TCP-сокеты; для UDP служит `DatagramSocket`.
- **Чтение до закрытия соединения.** TCP передаёт поток байтов без границ сообщений, и одно чтение в буфер фиксированного размера может вернуть только часть данных. `readAllBytes` читает всё до закрытия соединения клиентом, поэтому длина строки не ограничена.
- **Строка вводится до подключения.** Сервер обслуживает клиентов по очереди, поэтому клиент подключается только после ввода строки и не занимает сервер, пока пользователь печатает.
- **Кодировка.** `getBytes()` кодирует строку в байты, `new String(...)` декодирует обратно; с Java 18 обе стороны по умолчанию используют UTF-8, поэтому русские буквы передаются без искажений.
- **`ServerSocket` не закрывается явно.** Цикл бесконечный, сервер останавливается через Ctrl+C, и при завершении программы ОС сама закрывает её сокеты.

## Результаты

- Пока сервер работает, `netstat -an | grep 5050` показывает `tcp46 … *.5050 … LISTEN`: Java открывает один TCP-сокет на всех интерфейсах, который принимает подключения и по IPv4, и по IPv6.
- Строки на русском и английском доходят до сервера без искажений; при подключении по адресу `192.168.1.12` (адрес компьютера автора в сети 192.168.1.0/24) сервер так же получает строку и печатает адрес клиента `/192.168.1.12`.
- Строка длиной 140 000 байт (70 000 букв «я» в UTF-8) получена сервером полностью.
- Клиенты обслуживаются по очереди: пока первое соединение удерживается открытым 3 с, второй клиент успевает отправить строку и завершиться (его подключение ждёт в очереди ОС), а сервер печатает эту строку только после закрытия первого соединения.
