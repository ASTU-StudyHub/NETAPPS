# Лабораторная работа №4 — Сканер локальной сети: активные IP-адреса и открытые порты

Программа перебирает адреса локальной сети `192.168.1.0/24`, от `192.168.1.1` до `192.168.1.254`, и на каждом пробует подключиться по TCP к популярным портам: 21 (FTP), 22 (SSH), 23 (Telnet), 53 (DNS), 80 (HTTP), 139 (NetBIOS), 443 (HTTPS), 445 (SMB), 3389 (RDP), 8080. Печатаются найденные в сети адреса и их открытые порты. Файл: `NetScan.java` — программа.

## Запуск

Нужна Java 25 или новее. Из папки `lab4`:

```bash
java NetScan.java
```

Сеть задаётся строкой `String network = "192.168.1.";`: к ней дописываются числа от 1 до 254, поэтому поддерживается только сеть с маской `/24` (в домашних сетях она почти всегда такая). Свою сеть нужно вписать вручную. Её показывает `ipconfig` (Windows) или `ifconfig` (macOS, Linux): например, `inet 192.168.1.12 netmask 0xffffff00` — это адрес `192.168.1.12` с маской `255.255.255.0` (`/24`), в `network` пишутся первые три числа с точкой на конце. Программа завершается сама после проверки всех адресов.

## Пример вывода

```
Сканирование 192.168.1.0/24
192.168.1.12 открытые порты: [53]
192.168.1.1 открытые порты: [53, 80]
192.168.1.2 открытые порты: []
192.168.1.4 открытые порты: []
```

`192.168.1.1` — роутер (DNS и веб-интерфейс), `192.168.1.12` — компьютер, на котором запущен сканер (порт 53 на нём открывает другая программа, в некоторых запусках он был закрыт), остальные — устройства без открытых портов из списка. Адреса выводятся не по порядку: потоки заканчивают в разное время, а свой компьютер отвечает сразу и выводится первым.

## Как это работает

- Для каждого адреса `new Thread(() -> scan(ip, ports)).start()` запускает отдельный поток: все 254 адреса проверяются одновременно.
- `String ip = network + i` заводится внутри цикла, потому что лямбда `() -> scan(ip, ports)` может использовать только переменные, которые больше не меняются, а `i` меняется.
- `scan` проверяет порты адреса по очереди: `new Socket()` создаёт TCP-сокет, `socket.connect(new InetSocketAddress(ip, port), 1500)` подключается с таймаутом 1,5 с.
- Результат подключения определяется по исключению: нет исключения — порт открыт и добавляется в список `open`; `ConnectException` («Connection refused») — порт закрыт, но устройство ответило отказом, значит оно есть в сети (`refused = true`); любое другое `IOException` — ответа нет. `ConnectException` — подкласс `IOException`, поэтому его `catch` стоит первым, иначе код не скомпилируется.
- `socket.close()` нужен только после удачного подключения: при неудаче `connect` закрывает сокет сам.
- Адрес печатается, если у него есть открытый порт или был отказ: `if (!open.isEmpty() || refused)`.

## Особенности реализации

- **Завершение без ожидания потоков.** `main` заканчивается сразу после запуска потоков, но Java не завершает программу, пока работает хотя бы один обычный (не daemon) поток, поэтому программа заканчивается вместе с последним потоком.
- **Отказ — признак устройства.** Отказ (`ConnectException`) отправляет само устройство, значит оно существует, даже если все порты из списка закрыты. Если засчитывать только открытые порты, в этой сети нашлись бы только роутер и сам компьютер.
- **Остальные исключения.** `SocketTimeoutException` («Connect timed out») — за 1,5 с ответа не было: устройство молча отбрасывает подключение или адреса нет. `SocketException` («Host is down») — macOS несколько секунд безуспешно спрашивала по ARP, у кого этот адрес, и потом какое-то время отвечает так сразу. Оба случая попадают в пустой `catch (IOException e) {}` и не считаются отказом, поэтому адреса без устройств не печатаются.
- **Таймаут 1,5 с.** Открытый порт отвечает за миллисекунды, а отказ от устройств сети приходит на компьютере автора примерно через 1 с: с таймаутом 0,9 с отказы не успевали прийти.
- **Порты одного адреса — по очереди.** Устройство, которое отказывает на всех портах, проверяется около 10 с, молчащее — до 10 × 1,5 = 15 с. Все 2540 проверок сразу заняли бы около 2,5 с, но результаты портов пришлось бы собирать по адресам, и код стал бы заметно длиннее.
- **TCP вместо ping.** На macOS и Linux без прав root `InetAddress.isReachable` не отправляет ping, а подключается по TCP к порту 7 — то же, что делает эта программа, только с одним портом. Системный `ping` пришлось бы запускать как отдельную программу, а ключи у него разные в Windows, macOS и Linux.
- **Сеть задаётся вручную.** Автоматически сеть не определяется: при включённом VPN система считает главным VPN-интерфейс, и программа сканировала бы не ту сеть.

## Результаты

- В сети 192.168.1.0/24 сканер находит те же адреса, что отвечают на `ping`: в запуске из примера — четыре адреса выше; в повторном запуске — `192.168.1.1`, `192.168.1.2`, `192.168.1.10`, `192.168.1.12`, и перебор `ping` по всем 254 адресам дал те же четыре.
- Устройства появляются и пропадают: в одном из запусков `192.168.1.4` не ответил ни на `ping`, ни на подключения и не нашёлся.
- Время ответа на компьютере автора: открытый порт — 3–25 мс (у роутера на портах 53 и 80 — 3–6 мс), отказ — 1004–1024 мс, таймаут — 1,5 с. Для отсутствующего `192.168.1.4` первые три порта дали таймаут, остальные — мгновенный «Host is down»; адрес проверен за 4,5 с и не напечатан.
- После неудачного `connect` сокет закрыт (`isClosed()` равно `true`) и при отказе, и при таймауте.
- Всё сканирование вместе с запуском программы заняло 10,5–16 с; время определяет самое медленное устройство, отказывающее на всех 10 портах.
