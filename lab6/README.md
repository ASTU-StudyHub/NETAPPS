# Лабораторная работа №6 — Чат на TCP-сокетах: личные, групповые и общие сообщения, передача файлов

Программа реализует чат из сервера и консольных клиентов: клиенты подключаются к серверу по адресу `IP:порт` и обмениваются сообщениями и файлами в трёх режимах — общем (всем), групповом (участникам группы, которую создаёт любой клиент) и личном (одному клиенту по имени). Сервер хранит список клиентов и при каждом подключении и отключении, в том числе при обрыве связи, рассылает всем новый список. Файлы: `Server.java` — сервер, `Client.java` — консольный клиент.

## Запуск

Нужна Java 25 или новее. Из папки `lab6`:

```bash
java Server.java   # в первом терминале, остановка — Ctrl+C
java Client.java   # в других терминалах или на других компьютерах сети
```

Клиент запрашивает адрес сервера (`127.0.0.1:5051` на том же компьютере, с другого компьютера — IP-адрес сервера в сети, например `192.168.1.12:5051`) и имя без пробелов. Каждая строка ввода — `<адресат> <текст>`:

| Ввод | Действие |
|---|---|
| `* текст` | сообщение всем |
| `Борис текст` | личное сообщение Борису |
| `#проект текст` | сообщение участникам группы `#проект` |
| `Борис /file отчёт.txt` | файл Борису (так же `* /file …` и `#проект /file …`) |
| `/group #проект Аня Вика` | создать группу (создатель входит в неё сам) |

Полученный файл сохраняется в текущую папку с приставкой `получено_`. Выход из клиента — Ctrl+C или Ctrl+D. Порт задан в строке `new ServerSocket(5051)` в `Server.java`.

## Как это работает

- Протокол — строки UTF-8 (кодировка по умолчанию начиная с Java 18, поэтому в `InputStreamReader` и `PrintWriter` она не указана): первая строка от клиента — имя, дальше `<адресат> <текст>`. Строки читает `BufferedReader.readLine()`, пишет `PrintWriter.println()`; аргумент `true` в конструкторе `PrintWriter` включает отправку после каждой строки.
- Сервер в цикле принимает подключения `server.accept()` и на каждого клиента запускает поток с методом `handle`. `clients` — словарь «имя → `PrintWriter` сокета» (`LinkedHashMap` сохраняет порядок входа), `groups` — «#группа → имена».
- `route()` отделяет адресата через `split(" ", 2)`: `*` — всем, группа — её участникам, имя — только этому клиенту, иначе отправителю приходит `Нет адресата …`. В команде `/group` к тексту дописывается имя создателя; после `split(" +")` первое слово — группа, остальные — участники (`LinkedHashSet` убирает повторы и сохраняет порядок).
- При отключении клиента `readLine()` возвращает `null`, при сброшенном соединении — бросает `IOException`. В обоих случаях `leave()` закрывает сокет (через `out.close()`), удаляет клиента и рассылает список.
- Клиент заменяет `/file <путь>` на `/file <base64> <имя файла>` (`strip()` убирает пробел после пути, перетащенного в терминал), сервер пересылает строку как обычный текст, получатель декодирует base64 и сохраняет файл.
- В клиенте главный поток читает клавиатуру (по Ctrl+D `IO.readln()` возвращает `null`, и клиент закрывает сокет), а поток `read` печатает строки от сервера и после закрытия соединения выводит `Соединение закрыто` и вызывает `System.exit(0)`.

## Особенности реализации

- **Потоки.** `accept()` и `readLine()` блокируют поток до прихода данных. Без отдельных потоков сервер обслуживал бы одного клиента, а клиент не мог бы одновременно ждать ввод с клавиатуры и сообщения.
- **Синхронизация.** Методы, работающие с `clients` и `groups`, объявлены `synchronized`: в них одновременно находится только один поток. Поэтому строки с файлами не перемешиваются в сокете, а последним каждый клиент получает актуальный список. Вызывать эти методы друг из друга можно: поток повторно берёт уже захваченную им блокировку.
- **Ошибки записи.** `PrintWriter` не бросает исключений при ошибке записи, поэтому отключившийся получатель не прерывает поток отправителя.
- **base64.** Протокол построчный, а в файле могут быть `\n` и байты, которые не читаются как UTF-8. base64 превращает любые байты в буквы, цифры и `+/=`; объём при этом увеличивается на треть.
- **Оборванная строка.** Строку, оборванную на середине, `readLine()` тоже возвращает, и сервер её пересылает, но без имени файла после base64 получатель печатает её как текст, а не сохраняет повреждённый файл.
- **Копия отправителю.** Отправитель входит во «всех» и в группу, поэтому получает копию своего сообщения или файла; приставка `получено_` не даёт затереть исходный файл.
- **Ошибка подключения.** Чтение адреса и подключение стоят в `try`: если адрес введён не в виде `IP:порт`, порт не число или сервер не запущен, клиент печатает `Не удалось подключиться: нужен адрес вида IP:порт и запущенный сервер` и завершается.
- **Имя.** Пробелы по краям имени убирает `strip()`, поэтому «Вика » и «Вика» — одно и то же имя. Если вместо имени нажать Ctrl+D, `IO.readln()` возвращает `null`, `Objects.toString(…, "")` превращает его в пустую строку, и сервер отклоняет пустое имя.
- **Подключения без имени.** Подключение, не приславшее имя (например, сканер портов), и клиент с пустым или занятым именем получают `Имя пустое или занято` и в список не попадают.
- **Обнаружение обрыва.** Когда клиент закрыт или убит, ОС закрывает его сокет, и сервер сразу получает конец потока или ошибку. Если связь пропала молча (например, отключён кабель), TCP заметит это только при следующей отправке, через несколько минут.

## Результаты

- Сообщения доходят только до адресатов: в примере «Всем привет!» получили все три клиента, «Как дела?» — только Борис, сообщения и файл для `#проект` — только участники группы Аня и Борис.
- Файлы передаются без искажений: случайный двоичный файл 204 800 байт, отправленный в группу, и файл 10 485 760 байт (10 МБ), отправленный лично, совпали с исходными байт в байт (`cmp`). Через `127.0.0.1` файл 10 МБ доходит за 0,2–0,4 с (на компьютере автора).
- Путь с пробелом на конце принимается; для несуществующего файла клиент печатает `Нет файла нет.txt`, для неизвестного адресата сервер отвечает `Нет адресата Никто`.
- После `kill -9` процесса клиента сервер разослал новый список менее чем через 0,5 с. Подключение `nc -z 127.0.0.1 5051` сервер отметил только строкой `Подключение …`; второй клиент «Аня» получил `Имя пустое или занято` и `Соединение закрыто`.
- Строку `* /file QUJD` без перевода строки, отправленную клиентом «Гость» через `nc` перед закрытием соединения, сервер переслал, а клиенты напечатали её как `Гость всем: /file QUJD` и файла не создали.
- При трёх клиентах `lsof -nP -iTCP:5051` показывает у сервера сокет `*:5051 (LISTEN)` — порт открыт на всех интерфейсах — и по одному соединению `ESTABLISHED` на каждого клиента.
- По Ctrl+D и при остановке сервера клиент печатает `Соединение закрыто` и завершается.
- Адреса `127.0.0.1 5051`, `127.0.0.1:abc`, `localhost`, пустая строка, Ctrl+D вместо адреса и адрес незапущенного сервера дают сообщение `Не удалось подключиться…` без трассировки исключения; адрес с пробелами по краям подключается.
- Клиент с именем «Вика  » попадает в список как `Вика` и получает личные сообщения для `Вика`; второй клиент «Вика» получает `Имя пустое или занято`. После Ctrl+D вместо имени сервер печатает только `Подключение …`, в список никто не добавляется.
