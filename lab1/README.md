# Лабораторная работа №1 — Ответ на запросы по протоколам HTTP, FILE и DNS

Программа выполняет три запроса и печатает ответы: по HTTP получает страницу `http://example.com`, по протоколу FILE — собственный исходный текст по адресу `file:///…`, через DNS — IP-адреса хоста `example.com`. Файл: `Fetch.java` — программа.

## Запуск

Нужна Java 25 или новее. Из папки `lab1`:

```bash
java Fetch.java
```

Другой сайт задаётся в строке `String host = "example.com";`.

## Пример вывода

```
HTTP: <!doctype html><html lang=en><head>…<title>Example Domain</title>…</html>

FILE: void main() throws Exception {
    String host = "example.com";
…

DNS: [example.com/104.20.23.154, example.com/172.66.147.243, example.com/2606:4700:10:0:0:0:6814:179a, example.com/2606:4700:10:0:0:0:ac42:93f3]
```

HTML страницы и текст программы сокращены. Каждый адрес DNS печатается как `имя/адрес`, IPv6 — в полной форме, без сокращения `::`.

## Как это работает

- `toURL().openStream()` открывает адрес и выбирает обработчик по его схеме: для `http://` (адрес из `URI.create("http://" + host)`) отправляет на сервер HTTP-запрос GET, для `file:` открывает файл на диске. Один и тот же вызов обслуживает оба протокола.
- `readAllBytes()` читает тело ответа в байтах, `new String(...)` переводит байты в строку (UTF-8).
- `Path.of("Fetch.java").toUri()` превращает путь к программе в адрес вида `file:///…/lab1/Fetch.java`: делает путь абсолютным (от текущей папки) и заменяет пробелы и русские буквы на `%XX`.
- `InetAddress.getAllByName(host)` обращается к системному DNS-резолверу и возвращает все адреса хоста: IPv4 (записи A) и IPv6 (AAAA). Сверить можно командой `nslookup example.com`.
- `void main()` без класса — компактный исходный файл Java 25: класс создаётся неявно, классы из `java.base` (`URI`, `Path`, `InetAddress`, `Arrays`) доступны без `import`, `IO.println` печатает строку.

## Особенности реализации

- **Запрос по протоколу FILE, а не чтение файла.** Файл читается не через `Files.readString`, а через `URL` с адресом `file:///…`, то есть тем же механизмом `openStream()`, что и страница по HTTP.
- **Код ответа.** `openStream()` возвращает тело только при успешном ответе; при 4xx/5xx бросается `IOException` (`Server returned HTTP response code: 403 …`, для 404 — его подкласс `FileNotFoundException`), при несуществующем хосте — `UnknownHostException`. У `file:` кода ответа нет: это не HTTP.
- **Перенаправления.** `ya.ru` и `github.com` на `http://` отвечают `301` с переходом на `https://`, а Java сама переходит по перенаправлениям только в пределах того же протокола, поэтому HTTP-ответ получается пустым. Для демонстрации выбран `example.com`, который отвечает по HTTP без перенаправления.
- **`throws Exception`.** `toURL()`, `openStream()` и `getAllByName()` бросают проверяемые исключения, и Java требует их обработать или объявить. При ошибке программа завершается с описанием исключения.
- **Запуск только из `lab1`.** Путь `Fetch.java` относительный и отсчитывается от текущей папки; из другой папки запрос FILE завершается `FileNotFoundException`.

## Результаты

- HTTP: получена страница «Example Domain» — 577 байт HTML от `<!doctype html>` до `</html>`; `curl http://example.com` в момент проверки вернул код 200 и столько же байт.
- FILE: напечатанный текст байт в байт совпадает с файлом `Fetch.java` (353 байта, проверено `cmp`).
- DNS: два адреса IPv4 и два IPv6 — тот же набор, что выдаёт системный резолвер (`dscacheutil -q host -a name example.com` на macOS); порядок адресов от запуска к запуску меняется.
- Для `github.com` и `ya.ru` строка `HTTP:` пустая, сервер отвечает `301` с `Location: https://…`; для несуществующего хоста `no-such-host.invalid` программа завершается `UnknownHostException`, при запуске из другой папки — `FileNotFoundException`.
- Запуск вместе с компиляцией исходного файла занимает около 1 с на компьютере автора.
