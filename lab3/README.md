# Лабораторная работа №3 — Сканер открытых портов локального IP-адреса

Программа по очереди пробует подключиться по TCP ко всем портам 1–65535 адреса `127.0.0.1` и печатает те, где подключение удалось, то есть где работает сервер. Файл: `PortScan.java` — программа.

## Запуск

Нужна Java 25 или новее. Из папки `lab3`:

```bash
java PortScan.java
```

Другой адрес задаётся в строке `String host = "127.0.0.1";`. Для проверки можно в соседнем терминале запустить сервер из лабораторной работы №2 (`cd ../lab2 && java Server.java`): в списке появится `Открыт порт 5050`.

## Пример вывода

Сканер при запущенном сервере из лабораторной работы №2:

```
Открыт порт 631
Открыт порт 5000
Открыт порт 5037
Открыт порт 5050
Открыт порт 5554
Открыт порт 5555
…
Открыт порт 63342
Открыт порт 63343
Открыт порт 64644
```

Сервер из лабораторной работы №2:

```
/127.0.0.1:54786 
```

Сканер подключается и сразу закрывает соединение, ничего не отправив, поэтому сервер печатает адрес сканера и пустую строку.

## Как это работает

- `new Socket(host, port)` создаёт TCP-сокет и сразу подключается (SYN → SYN-ACK → ACK). Если подключение удалось, порт открыт: `close()` закрывает соединение, `IO.println` печатает номер.
- На закрытом порту ОС отвечает отказом (RST), и конструктор бросает `ConnectException: Connection refused`. Для сканера это не ошибка, а обычный ответ «порт закрыт», поэтому `catch` пустой: печатать нечего, цикл переходит к следующему порту.
- Перехватывается `IOException` — родитель `ConnectException`, — потому что `close()` тоже может бросить `IOException`. Так все проверяемые исключения обработаны, и `throws Exception` у `main` не нужен.

## Особенности реализации

- **Адрес `127.0.0.1`.** Он есть на любом компьютере, и через него видны все серверы: и слушающие только `127.0.0.1`, и слушающие все адреса. С адресом компьютера в сети (`String host = "192.168.1.12";`) находятся только серверы на всех адресах (`*` в `netstat`), то есть доступные из сети.
- **Без таймаута.** На своём компьютере ответ приходит сразу: соединение или отказ. Таймаут нужен при сканировании чужих компьютеров, где брандмауэр может молча отбрасывать пакеты и подключение долго ждало бы ответа; тогда пишут `new Socket()` и `connect(new InetSocketAddress(host, port), 200)` — ожидание не больше 200 мс.
- **Без потоков.** На `127.0.0.1` отказ приходит мгновенно, поэтому 65 535 попыток подряд укладываются примерно в 4 с.
- **Сокеты не копятся.** Если подключиться не удалось, конструктор сам закрывает свой сокет (в исходниках JDK конструктор `Socket` вызывает `closeSuppressingExceptions` в `catch`), поэтому незакрытые сокеты не накапливаются.
- **Только IPv4.** Сканер подключается к IPv4-адресу, поэтому порты, которые слушаются только на IPv6-адресе `::1`, он не видит.
- **Только TCP.** UDP-порты не проверяются: `Socket` работает только по TCP, а у UDP нет установления соединения, поэтому `DatagramSocket.connect` «подключается» к любому порту, и открытый порт от закрытого так не отличить.

## Результаты

- Список совпадает с портами `tcp4`/`tcp46` с адресом `127.0.0.1` или `*` в выводе `netstat -an -p tcp | grep LISTEN`: на компьютере автора — 27 из 27, без лишних и пропущенных.
- Порты, которые слушаются только на `::1` (`tcp6` в `netstat`), в списке отсутствуют.
- Программу, которая держит порт, показывает `lsof -nP -iTCP -sTCP:LISTEN` (без `sudo` — только программы текущего пользователя): например, порты 5000 и 7000 на macOS занимает AirPlay.
- Полный перебор на компьютере автора занимает 4,1–4,2 с, из них 0,3–0,6 с — запуск Java.
- С лимитом в 256 открытых файлов (`ulimit -Hn 256` в zsh) находятся те же порты.
- Сервер из лабораторной работы №2 найден на порту 5050 и напечатал подключение сканера.
- Подключение к закрытому порту 1 бросает `java.net.ConnectException: Connection refused`, а `DatagramSocket.connect` к тому же порту проходит без ошибки.
